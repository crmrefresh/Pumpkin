Assumptions this tool makes
  • Columns on both files are auto-detected by header name and listed in the Column mapping block, where you can override any of them. First and last name must be mapped on both files before the tool will run.
  • Each candidate scores points for what the two records share: 55 for an exact first + last name, 50 for a nickname, 30 for a matching email, 26 for a matching phone, 9 for an identical street, 4 for a matching zip. 50 is the bar to clear. Names are compared with accents, punctuation and suffixes (Jr, III, MD) stripped.
  • A merge on the name alone is allowed only when that name appears exactly once in each file — nicknames folded together, so Rob and Robert count as the same person when checking. Where it appears more than once on either side, the merge has to be backed by a matching email or phone instead.
  • A name match needs a first and a last name on both sides. A phone contact saved as just "Rob", or a Compass row holding only "Robert", never matches on the name alone — though either will still merge if an email or phone identifies them. A Compass row with no name at all is matched on email or phone and has its name written in.
  • Where several Compass rows match one contact, the merge only goes into the row that also shares a direct email or phone, and only if exactly one row does. Where several phone contacts land on one Compass row, none of them merge.
  • A Compass row with no name at all is matched on email or phone alone, and has its first and last name written in from the phone export.
  • Every contact either clears the parameters or it does not — there is no review queue. Where the tool is in doubt it writes nothing and moves on, which is always the safer error: an unmerged contact still shows up in the Full Phone File with a blank Compass email.
  • An email or phone that belongs to exactly one contact in each file identifies that person on its own, provided the first names do not contradict each other. A missing, shortened or initialised first name cannot contradict anything, and a changed surname does not block it; two plainly different first names do. One that sits on more than one contact in either file — an office line, an info@ address, a shared mobile — is ignored for identification altogether.
  • Phones are compared as digits only, last ten, leading 1 dropped, so formatting differences never block a match. Nothing is reformatted on the way out: values are written exactly as the phone file has them. Dates are the one exception — they are written as MM/DD/YYYY so Compass reads them.
  • A single-column address is split into line 1, line 2, city, state and zip; trailing country lines are dropped. Where the phone export already splits them, those columns are used as-is.
  • If the Compass export has no column for something the phone file holds — no Birth Date column, say — that column is created at the end of the file rather than the data being dropped. It takes the Compass field name, so it re-imports cleanly.
  • A birth date stamped with the current year or later has no real year in it: phones fill in today's when you save a birthday without one. The day and month are kept and the year dropped.
  • Existing Compass values are never overwritten, reformatted or removed. Original columns and row order stay exactly as exported; conflicting phone values are appended as "(Phone)" columns at the end. Every updated row is tagged "CRM: Phone Contact Match".
  • These phone columns are ignored on purpose: gender, categories, web page, related name, department, country, country code, pager, business fax, home fax, nickname, display name.
  • The Full Phone File is cleaned on the way out, and only there — the merge itself never reformats anything. Numbers are rewritten as 954-555-0123 where ten digits are present, control characters, emoji and stray punctuation are stripped, values that are only symbols or placeholders ("n/a", "unknown") are blanked, and three kinds of column are dropped: phone and email type columns, full-name or display-name columns, and any column that is empty from top to bottom.
  • All three files end with a Change log column reading "Matched on name + email (85) | Filled: Primary Mobile Number = 954-555-0123 | New column: Primary Email (Phone) = old@address.com". In the phone file it also records why a contact did not merge.
  • This runs entirely in your browser — no data leaves your machine.
